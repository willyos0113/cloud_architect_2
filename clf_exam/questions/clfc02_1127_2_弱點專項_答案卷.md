## 詳解

## 一、Artifact 與 Audit Manager

**1.** 答案：**B**

Artifact 提供 AWS 本身的合規報告，例如 ISO 27001、SOC 報告，可以直接下載。
易混淆：Audit Manager 蒐集的是客戶自己使用 AWS 的稽核證據，不是 AWS 的報告。

👉 AWS 資料中心、AWS 的認證報告 -> Artifact。

**2.** 答案：**C**

Audit Manager 自動蒐集客戶自己帳戶中的證據，並對照合規框架（如 PCI DSS）的控制項產生稽核報告。
易混淆：Artifact 是 AWS 自己的報告；CloudTrail 只記錄 API 活動，不會自動對照控制項產生報告。

👉 公司自己的證據、對照控制項、自動化 -> Audit Manager。

**3.** 答案：**D**

Artifact 除了報告之外，也提供 Agreements，讓客戶檢視與簽署 BAA 等協議。
易混淆：Audit Manager 不處理協議，它處理的是稽核證據。

👉 AWS 的報告與協議（BAA）-> Artifact。

**4.** 答案：**AC**

Audit Manager 提供預先建置的合規框架，並持續自動蒐集客戶自己環境中的證據。
易混淆：B 與 E 是 Artifact 的功能；D 是 GuardDuty 的功能。

👉 Audit Manager：框架、控制項、客戶自己的證據、持續蒐集。

**5.** 答案：**C**

Artifact 是 AWS 提供給客戶的合規報告與協議；Audit Manager 是蒐集客戶自己環境的稽核證據。
易混淆：A 把兩者對調；只要記住「誰的證據」就不會混淆：Artifact 是 AWS 的，Audit Manager 是你的。

👉 AWS 的 -> Artifact；你自己的 -> Audit Manager。

**6.** 答案：**AB**

AWS 資料中心的控制報告，從 Artifact 下載；公司自己帳戶的存取控制證據，由 Audit Manager 蒐集。
易混淆：GuardDuty 偵測威脅、Inspector 掃描漏洞、Macie 找敏感資料，都不是為稽核蒐集證據的服務。

👉 稽核兩端：AWS 的那一半 -> Artifact；自己的那一半 -> Audit Manager。

## 二、計價方案

**7.** 答案：**D**

短期、不可中斷、不綁約，是 On-Demand 的情境。
易混淆：Spot 雖然最便宜，但可能被中斷，題目說被中斷就要重來；Savings Plans 與 RI 都需要一到三年的承諾。

👉 短期、不可中斷、不綁約 -> On-Demand。

**8.** 答案：**B**

Compute Savings Plans 承諾每小時花費，自動適用 EC2、Fargate 與 Lambda。
易混淆：EC2 Instance Savings Plans 才只適用 EC2；Lambda 沒有 Reserved Instances 這種方案。

👉 Compute SP 涵蓋 EC2、Fargate、Lambda；EC2 Instance SP 只涵蓋 EC2。

**9.** 答案：**C**

任務可以重跑、被中斷也能接受、成本最低，是 Spot 的典型情境。
易混淆：RI 與 Savings Plans 適合穩定長期用量，而不是以最低成本為目標。

👉 可中斷、可重跑、成本最低 -> Spot。

**10.** 答案：**A**

RI 與 Savings Plans 都是以一年或三年的使用承諾換取折扣。
易混淆：它們都不能保證 Spot 容量，也不能隨時全額退費；Savings Plans 也不只適用 EC2。

👉 RI 與 Savings Plans 都是「承諾換折扣」。

**11.** 答案：**B**

Compute Savings Plans 可更換家族與 Region，並涵蓋 Fargate 與 Lambda。
易混淆：EC2 Instance Savings Plans 綁定特定 Region 與家族，彈性較低，折扣較高。

👉 彈性：Compute SP > EC2 Instance SP；折扣反過來。

## 三、Lambda／Beanstalk／Lightsail 與 Secrets Manager／KMS／ACM

**12.** 答案：**C**

ACM 佈建、管理與自動續期 SSL/TLS 憑證，用在 HTTPS。
易混淆：Secrets Manager 的 credentials 是登入用的帳號密碼等機密，不是網站連線的憑證；KMS 管的是加密金鑰。

👉 HTTPS 的 SSL/TLS 憑證 -> ACM；帳密與 API 金鑰 -> Secrets Manager；加密金鑰 -> KMS。

**13.** 答案：**B**

Lightsail 是簡化的方案，把虛擬伺服器、儲存、網路與靜態 IP 打包起來，固定月費，適合小型網站與部落格。
易混淆：EC2 要自己設定網路與計價較複雜；Lambda 不是長時間執行的網站主機；Beanstalk 是用於部署應用程式。

👉 小型網站、打包好、固定月費、不用研究 VPC -> Lightsail。

**14.** 答案：**D**

Beanstalk 讓開發者上傳現有的 Web 應用程式，由 AWS 佈建 EC2、負載平衡與 Auto Scaling，不需要重寫成函式。
易混淆：Lambda 需要把程式改寫成事件觸發的函式；CodeDeploy 只佈署程式碼，CloudFormation 要自己用範本定義每個資源。

👉 現有應用程式、不想自己設定 EC2 與 ALB -> Beanstalk。

**15.** 答案：**A**

Secrets Manager 存放 API 金鑰、密碼等機密，程式執行時再取得，並可自動輪替。
易混淆：KMS 管的是加密金鑰，不是儲存與輪替 API 金鑰；ACM 是 SSL/TLS 憑證。

👉 API 金鑰、密碼、自動輪替 -> Secrets Manager。

## 詳解

## 一、計價方案

**1.** 答案：**C**

穩定、長期、家族與 Region 都確定，Standard Reserved Instances 綁約一到三年，折扣最大。
易混淆：Spot 可能被中斷，不適合資料庫；Dedicated Hosts 是為授權或合規需求，不是為了省錢。

👉 穩定長期、家族與 Region 固定 -> Standard RI。

**2.** 答案：**B**

Compute Savings Plans 承諾每小時花費，自動適用 EC2（可換家族與 Region）、Fargate 與 Lambda。
易混淆：Standard RI 與 EC2 Instance Savings Plans 都綁定家族，換了就不適用；Spot 不是承諾型方案。

👉 會換家族、換 Region、混用 Fargate／Lambda -> Compute Savings Plans。

**3.** 答案：**A**

可中斷、可重跑、成本最低，是 Spot 的典型情境，最多可省約 90%。
易混淆：RI 與 Savings Plans 適合穩定長期用量，不是以「最低成本、可中斷」為目標。

👉 可中斷、可重跑、批次 -> Spot。

**4.** 答案：**D**

短期、無法預測、不能中斷、不想承諾，是 On-Demand 的情境。
易混淆：Spot 會被中斷；RI 與 Savings Plans 需要一到三年的承諾。

👉 短期、不可預測、不可中斷、不綁約 -> On-Demand。

**5.** 答案：**B**

Savings Plans 承諾的是每小時的花費金額（美元／小時），不是特定的執行個體。
易混淆：「承諾特定執行個體類型」是 Reserved Instances 的做法。

👉 Savings Plans 承諾「花費」；RI 承諾「執行個體組態」。

**6.** 答案：**C**

Convertible RI 可以在期間內換成不同家族、作業系統或租用方式，折扣略低於 Standard RI。
易混淆：Standard RI 折扣較大，但期間內不能更換家族。

👉 要能換家族又想用 RI -> Convertible RI。

**7.** 答案：**AB**

Spot 可節省最多約 90%，但 AWS 需要容量時會回收執行個體，所以可能被中斷。
易混淆：Spot 不保證不中斷、也不用綁約；穩定連續執行的資料庫應該用 On-Demand、RI 或 Savings Plans。

👉 便宜約 90%、可能被中斷、不綁約 -> Spot。

**8.** 答案：**A**

Dedicated Hosts 是整台實體伺服器，可以看到實體 socket 與核心數，適合以 socket 或核心計價的 BYOL 授權。
易混淆：Dedicated Instances 是在專屬硬體上執行，但看不到 socket 與核心數，無法用來符合這類授權。

👉 要看到 socket／核心、BYOL 授權 -> Dedicated Hosts。

**9.** 答案：**B**

EC2 Instance Savings Plans 綁定特定 Region 與執行個體家族，彈性較低，折扣比 Compute Savings Plans 高。
易混淆：Compute Savings Plans 彈性最大，折扣較低；題目說願意接受較低的彈性。

👉 彈性：Compute SP > EC2 Instance SP；折扣反過來。

**10.** 答案：**D**

一般而言，期間越長、預付越多，折扣越大，所以三年期全額預付折扣最大。
易混淆：一年期或無預付的折扣較小，換到的是較低的現金流壓力。

👉 越久、越多預付 -> 折扣越大。

## 二、Route 53、Global Accelerator、CloudFront 與 ELB 的分工

**11.** 答案：**C**

CloudFront 是 CDN，把靜態內容快取在邊緣節點，降低延遲。
易混淆：Global Accelerator 不快取內容，只是用固定 IP 與骨幹網路改善路徑；Route 53 只做 DNS 解析。

👉 快取、邊緣、靜態內容 -> CloudFront。

**12.** 答案：**A**

Global Accelerator 提供固定的 Anycast IP，流量走 AWS 全球骨幹，故障切換不依賴 DNS 快取。
易混淆：Route 53 是 DNS，切換速度受 DNS 快取影響；NLB 只在單一 Region 內。

👉 固定 Anycast IP、骨幹網路、跨 Region -> Global Accelerator。

**13.** 答案：**D**

Route 53 的健康檢查搭配 Failover 路由政策，可以在 DNS 層自動切到備援。
易混淆：CloudFront 只快取內容；Global Accelerator 是用固定 IP 導流，不是 DNS。

👉 DNS、健康檢查、Failover 路由 -> Route 53。

**14.** 答案：**B**

ALB 運作在第七層，可以依 URL 路徑、主機名稱或標頭，把請求導向不同的目標群組。
易混淆：NLB 運作在第四層，只看 IP 與 Port，看不到 URL 路徑。

👉 依 URL 路徑、第七層 -> ALB。

**15.** 答案：**C**

NLB 運作在第四層，處理 TCP／UDP，效能極高，每個 AZ 提供一個靜態 IP。
易混淆：ALB 是第七層，用於 HTTP 路由；Route 53 不處理連線流量。

👉 第四層、極高效能、靜態 IP -> NLB。

**16.** 答案：**AC**

ALB 與 NLB 都只在單一 Region 內分配流量。
易混淆：Route 53 是全球性的 DNS 服務；Global Accelerator 可以跨 Region；CloudFront 在全球邊緣節點運作。

👉 ELB 與 Auto Scaling 只在單一 Region；跨 Region 靠 Route 53 或 Global Accelerator。

**17.** 答案：**C**

Route 53 的延遲路由政策（Latency-based routing）會把使用者導向延遲最低的 Region。
易混淆：ALB 與 Auto Scaling 只在單一 Region；CloudFront 是快取內容，不是 DNS 路由。

👉 DNS 層依延遲、地理位置選 Region -> Route 53。

**18.** 答案：**D**

Global Accelerator 支援 TCP 與 UDP，提供固定 IP 並走 AWS 骨幹網路，可以改善全球玩家的網路效能。
易混淆：CloudFront 用於 HTTP(S) 內容的快取；Route 53 只做名稱解析，不改善網路路徑。

👉 UDP、固定 IP、全球網路效能 -> Global Accelerator。

## 三、相似服務的分界

**19.** 答案：**A**

Secrets Manager 存放密碼、API 金鑰等機密，並可自動輪替資料庫憑證。
易混淆：KMS 管的是加密金鑰，不是儲存與輪替密碼。

👉 密碼、API 金鑰、自動輪替 -> Secrets Manager；加密金鑰 -> KMS。

**20.** 答案：**C**

KMS 建立與管理加密金鑰，可以和 S3、EBS 等服務整合做加密。
易混淆：Secrets Manager 存放密碼等機密；IAM 管的是身分與權限。

👉 加密金鑰 -> KMS。

**21.** 答案：**B**

Artifact 提供 AWS 本身的合規報告（例如 SOC、ISO）與協議的下載。
易混淆：Audit Manager 蒐集的是客戶自己使用 AWS 的稽核證據。

👉 下載「AWS 的」合規報告 -> Artifact。

**22.** 答案：**D**

Audit Manager 自動蒐集客戶自己帳戶中的證據，對照合規框架產生稽核報告。
易混淆：Artifact 是 AWS 自己的報告；Config 只記錄資源組態變更，不產出對照框架的稽核報告。

👉 蒐集「客戶自己的」稽核證據 -> Audit Manager。

**23.** 答案：**B**

GuardDuty 分析 CloudTrail、VPC Flow Logs 與 DNS 紀錄，偵測異常與惡意行為。
易混淆：Inspector 掃描的是軟體漏洞，不是帳戶行為；Macie 找的是 S3 裡的敏感資料。

👉 異常行為、威脅偵測 -> GuardDuty。

**24.** 答案：**A**

Inspector 掃描 EC2、容器映像與 Lambda 函數中的已知軟體漏洞。
易混淆：GuardDuty 偵測威脅行為，不掃漏洞；Shield 是防 DDoS。

👉 漏洞掃描、CVE -> Inspector。

**25.** 答案：**AC**

Inspector 掃描 EC2、容器映像與 Lambda，並持續自動掃描，用風險分數排序發現項目。
易混淆：分析 VPC Flow Logs 是 GuardDuty；找 PII 是 Macie；記錄組態變更是 Config。

👉 Inspector 掃漏洞；GuardDuty 看行為；Macie 看資料；Config 看組態。

**26.** 答案：**D**

Lambda 由事件觸發，不需管理伺服器，依執行次數與時間計費。
易混淆：Beanstalk 與 Lightsail 仍有伺服器要管理；EC2 更是。

👉 事件觸發、不管伺服器、依執行時間計費 -> Lambda。

**27.** 答案：**C**

Elastic Beanstalk 讓開發者上傳程式碼，由 AWS 佈建與管理 EC2、負載平衡與 Auto Scaling。
易混淆：CloudFormation 要自己用範本定義每個資源；CodeDeploy 只負責佈署程式碼，不建立基礎設施。

👉 上傳程式碼、AWS 代為佈建與管理 -> Beanstalk。

**28.** 答案：**A**

CloudFormation 以範本定義並建立整套基礎設施（IaC），可以重複建立相同環境。
易混淆：Beanstalk 是替你決定架構；CodeDeploy 不建立基礎設施。

👉 範本定義資源、IaC -> CloudFormation。

**29.** 答案：**D**

CodeDeploy 把應用程式的新版本自動佈署到既有的 EC2、Lambda 或地端伺服器，不負責建立基礎設施。
易混淆：CloudFormation 與 Beanstalk 都會建立基礎設施，題目說基礎設施已經建好。

👉 只佈署程式碼、基礎設施已存在 -> CodeDeploy。

**30.** 答案：**AB**

KMS 管理加密金鑰；Secrets Manager 可自動輪替資料庫憑證。
易混淆：C 是 Audit Manager 的功能（Artifact 是 AWS 自己的報告）；D 是 Inspector 的功能（GuardDuty 偵測威脅）；E 錯，Lambda 的作業系統由 AWS 管理。

👉 KMS 管金鑰；Secrets Manager 管機密；Artifact 下載報告；GuardDuty 看威脅；Lambda 不用管 OS。

## 詳解

## 一、運算與部署

**① Lightsail**

小型網站、打包好、固定月費、不用研究 VPC。
易混淆：EC2 要自己設定網路與計價複雜；Beanstalk 是用來部署應用程式；Lambda 不是長時間執行的網站主機。

👉 小型網站、固定月費、簡化 -> Lightsail。

**② Elastic Beanstalk、③ EC2**

上傳現有應用程式，由 AWS 佈建 EC2、負載平衡與 Auto Scaling，你仍可存取底層資源。
易混淆：CodeDeploy 只佈署程式碼，不建立環境；CloudFormation 要自己用範本定義每個資源；Lambda 要把程式改寫成函式。

👉 現有應用程式、不想自己設定 EC2 與 ALB -> Beanstalk。

**④ Lambda**

事件觸發、不管伺服器、依執行時間計費。
易混淆：Beanstalk 底下還是 EC2，不是無伺服器。

👉 事件觸發、不管伺服器 -> Lambda。

**⑤ CodeDeploy、⑥ CloudFormation、⑦ EC2**

CodeDeploy 只管把程式碼佈署出去，環境要自己有；CloudFormation 用範本把資源建出來；EC2 讓你完全掌控 OS 與軟體。
易混淆：CodeDeploy 與 Beanstalk 都跟「部署」有關，差在 Beanstalk 會幫你建環境，CodeDeploy 不會。

👉 只佈署程式碼 -> CodeDeploy；範本建資源 -> CloudFormation；完全控制 -> EC2。

**⑧ ⑨ ⑩ ⑪ ⑫ Lightsail、Beanstalk、CloudFormation、Lambda 的分界**

- Lightsail：打包好、固定月費，簡化。EC2：設定與計價較複雜。
- Beanstalk：你負責上傳程式碼，環境由 AWS 佈建。CloudFormation：你要自己用範本定義每個資源。
- Lambda：現有的 Web 應用程式不能直接搬，要先改寫成事件觸發的函式。

## 二、Secrets Manager、KMS、ACM

**⑬ Secrets Manager**

存放 API 金鑰、密碼等機密，程式執行時再取得，可自動輪替。
易混淆：KMS 管的是加密金鑰，不是儲存與輪替 API 金鑰。

**⑭ KMS、⑰ 金鑰**

建立與管理加密金鑰，不負責保存與輪替密碼或 API 金鑰。

**⑮ ACM**

佈建、管理、自動續期 SSL/TLS 憑證，用在 HTTPS。

**⑯ 登入用的帳號、密碼等機密**

credentials 中文常翻成「憑證」，但在 Secrets Manager 指的是登入用的帳密，不是網站連線的 SSL/TLS 憑證。

👉 帳密與 API 金鑰、輪替 -> Secrets Manager；加密金鑰 -> KMS；HTTPS 憑證 -> ACM。

## 三、Artifact 與 Audit Manager

**㉑ ㉒ Artifact**

Artifact 提供 AWS 本身的合規報告（ISO 27001、SOC 等），並提供 Agreements，讓客戶檢視與簽署 BAA 等協議。
易混淆：Audit Manager 不處理協議，也不是 AWS 的報告。

**㉓ Audit Manager**

自動蒐集客戶自己帳戶的證據，對照合規框架的控制項產生稽核報告。
易混淆：Artifact 是 AWS 自己的報告；CloudTrail 只記錄 API 活動，不會自動對照控制項。

**㉔ Artifact**

👉 AWS 的 -> Artifact；你自己的 -> Audit Manager。

## 四、計價方案

**㉕ On-Demand**

短期、不可中斷、不綁約。
易混淆：Spot 最便宜但可能被中斷；RI 與 Savings Plans 都要一到三年承諾。

**㉖ Spot**

可中斷、可重跑、成本最低。

**㉗ 使用承諾**

RI 與 Savings Plans 都是用一或三年的使用承諾換折扣。

**㉘ Fargate**

Compute Savings Plans 涵蓋 EC2、Fargate、Lambda；EC2 Instance Savings Plans 只涵蓋 EC2，綁定特定家族與 Region，彈性較低、折扣較高。

👉 不可中斷、不綁約 -> On-Demand；可中斷、最便宜 -> Spot；承諾換折扣 -> RI／Savings Plans。

## 五、零碎缺口

**㉙ Rehost**

6R 的完整分界：

| 策略       | 做法                                   |
| ---------- | -------------------------------------- |
| Rehost     | 原樣搬，不改程式碼與架構               |
| Replatform | 小幅調整，例如把自己架的資料庫換成 RDS |
| Refactor   | 重新設計，例如改成微服務或無伺服器     |
| Repurchase | 改買 SaaS 產品                         |
| Retire     | 不再使用，直接關閉                     |
| Retain     | 暫時保留在地端                         |

易混淆：Replatform 與 Refactor 的差別是「換成代管服務、小幅調整」對「重新設計架構」。

**㉚ Enterprise**

專屬 TAM -> Enterprise Support。支援方案各層級包含什麼，細節以教材與官方文件為準，我沒有逐項核對。

## 領域一：雲端概念

**1.** 答案：**B**

「幾分鐘內部署到全球」是 AWS 官方列出的雲端優勢之一（Go global in minutes）。
易混淆：彈性是跟著用量伸縮，規模經濟是用量大使單價下降，兩者都不是在講「跨地區快速部署」。

👉 一行口訣：多國同時上線、就近連線 -> Go global in minutes。

**2.** 答案：**C**

CAF 的 Governance 視角涵蓋治理與雲端財務管理（預算、成本可視性、成本管控）。
易混淆：Business 視角談的是業務價值與策略對齊，不是成本管控機制。

👉 一行口訣：預算、成本管控、風險治理 -> Governance；技能訓練、組織變革 -> People。

**3.** 答案：**D**

「IaC、小幅頻繁變更、事後檢討持續改善」是營運卓越的設計原則。
易混淆：可靠性談的是從故障復原與擴展；成本最佳化談的是花費效益。

👉 一行口訣：自動化、小步變更、事件後學習 -> 營運卓越。

**4.** 答案：**A**

「選對資源類型與大小、持續評估新技術」是效能效率的核心。
易混淆：成本最佳化也會談選對規格，但題目重點是「配合工作負載特性取得效能」，不是省錢。

👉 一行口訣：選對資源類型和規模 -> 效能效率；流程自動化、持續改善 -> 營運卓越。

**5.** 答案：**BD**

「Stop guessing capacity」與「Go global in minutes」都是官方列出的優勢。其餘三項是傳統地端的做法或對共同責任的誤解（安全是共同責任，不會完全轉移）。

👉 一行口訣：不用猜容量、幾分鐘全球部署 -> 雲端優勢；預先投資硬體 -> 地端思維。

**6.** 答案：**C**

永續性支柱的重點是降低環境影響、提高資源使用率與能源效率。
易混淆：成本最佳化也會減少閒置資源，但目標是省錢，不是環境影響。

👉 一行口訣：降低環境影響、能源效率 -> 永續性。

**7.** 答案：**D**

AZ 是同一個 Region 內，具有獨立電力、網路與冷卻的一或多個資料中心。
易混淆：(A) 是 Edge location；(B) 描述的是 Region；(C) 是 Local Zones。

👉 一行口訣：Region 由多個 AZ 組成；Region 地理獨立，AZ 之間電力、網路獨立。

**8.** 答案：**A**

CloudFront 的內容快取在 Edge location（邊緣站點），用來降低終端使用者延遲。
易混淆：AZ 和 Region 是用來放運算與儲存資源，不是內容快取站點。

👉 一行口訣：快取內容、靠近使用者 -> Edge location。

**9.** 答案：**C**

法規要求資料留在特定國家時，資料落地是選擇 Region 的第一優先，其次才是延遲、價格與服務可用性。

👉 一行口訣：選 Region 的順序：法規合規 -> 延遲 -> 服務可用 -> 價格。

**10.** 答案：**B**

Outposts 把 AWS 基礎設施、服務與 API 帶到客戶自己的資料中心，提供一致的混合體驗。
易混淆：Local Zones 與 Wavelength 是 AWS 擁有的延伸站點（都會區或 5G 邊緣），不是裝在客戶機房；Snowball Edge 主要用於離線資料搬移與邊緣運算。

👉 一行口訣：AWS 機櫃裝在自己機房 -> Outposts。

**11.** 答案：**A**

不改程式碼直接搬到 EC2 是 Rehost（Lift and shift），遷移最快。
易混淆：Refactor 要重新設計架構；Repurchase 是改買 SaaS；Retire 是直接淘汰。

👉 一行口訣：不改程式碼、直接搬 -> Rehost；改買 SaaS -> Repurchase。

**12.** 答案：**D**

改為訂閱 SaaS 取代自建系統是 Repurchase。
易混淆：Retire 是把不需要的應用關掉，不是換成別的產品；Relocate 是把 VMware 等環境搬到雲端而不變更。

👉 一行口訣：自建改訂閱 SaaS -> Repurchase。

**13.** 答案：**B**

員工技能、組織變革與人才缺口屬於 People 視角。

👉 一行口訣：技能與組織變革 -> People；成本與風險治理 -> Governance。

**14.** 答案：**BC**

可靠性原則包含「自動從故障復原」與「水平擴展以提高整體可用性」。其餘：人工復原、預購固定容量、依賴單一大型資源，都與原則相反。

👉 一行口訣：自動復原、水平擴展、不猜容量 -> 可靠性。

**15.** 答案：**C**

跨 Region 還原系統與資料屬於災難復原。
易混淆：高可用性（多 AZ）處理的是單一資料中心故障，不是整個 Region 中斷。

👉 一行口訣：多 AZ -> 高可用；跨 Region 還原 -> 災難復原。

**16.** 答案：**D**

從數週縮短到數分鐘、加速創新，是敏捷性。
易混淆：彈性是容量跟著需求伸縮，與「取得資源的速度」不同。

👉 一行口訣：取得資源變快、加速創新 -> 敏捷性；容量跟著需求伸縮 -> 彈性。

## 領域二：安全與合規

**17.** 答案：**A**

使用 EC2 時，客體作業系統的修補是客戶責任；實體安全、Hypervisor、網路硬體是 AWS 責任。

👉 一行口訣：EC2：OS 以上歸客戶；機房、Hypervisor 以下歸 AWS。

**18.** 答案：**D**

RDS 是託管服務，資料庫引擎與底層作業系統的修補由 AWS 負責。帳號權限、資料表設計、安全群組仍是客戶責任。

👉 一行口訣：託管服務 -> AWS 管引擎與 OS，客戶管資料與存取。

**19.** 答案：**B**

root 要啟用 MFA，不建立 access key，日常改用 IAM 身分。其餘選項都會增加憑證外洩風險。

👉 一行口訣：root：MFA + 不開 access key + 不日常使用。

**20.** 答案：**C**

為 EC2 指派 IAM Role，認證由 AWS 自動提供並定期輪替，不需要在機器上放長期金鑰。
易混淆：把 key 放環境變數或設定檔，仍是長期憑證，仍有外洩風險。

👉 一行口訣：服務要呼叫 AWS API -> IAM Role，不放 access key。

**21.** 答案：**A**

最小權限：只給完成工作所需的動作與資源。先給大權限再收回，期間就有風險。

👉 一行口訣：只給需要的動作和資源 -> 最小權限。

**22.** 答案：**AD**

啟用 MFA、用群組管理權限，都是 IAM 最佳實務。共用認證、日常使用 root、長期 key 不輪替都違反建議。

👉 一行口訣：MFA、群組授權、輪替憑證。

**23.** 答案：**B**

IAM Identity Center 用於集中管理多帳號的員工單一登入，可串接公司的身分來源。
易混淆：Cognito 是面向應用程式的終端消費者；本題是員工存取 AWS 帳號。（教材與考試以此為準）

👉 一行口訣：員工、多帳號、單一登入 -> Identity Center；App 消費者登入 -> Cognito。

**24.** 答案：**D**

Cognito 提供行動與網頁 App 的使用者註冊、登入，並支援社群身分。
易混淆：IAM User 與 Identity Center 是給管理 AWS 資源的員工，不是 App 的終端消費者。

👉 一行口訣：App 消費者、社群登入 -> Cognito。

**25.** 答案：**C**

SCP 設定的是組織內帳號的權限上限，帳號管理員也無法超越。
易混淆：IAM 身分型政策是在帳號內授權；NACL 與安全群組是網路層控制。

👉 一行口訣：組織層級的權限上限 -> SCP。

**26.** 答案：**A**

KMS 建立與管理加密金鑰，使用紀錄會記錄在 CloudTrail。
易混淆：Secrets Manager 存放密碼等機密並自動輪替；ACM 管理 TLS 憑證。

👉 一行口訣：加密金鑰 -> KMS；密碼自動輪替 -> Secrets Manager；TLS 憑證 -> ACM。

**27.** 答案：**B**

Secrets Manager 儲存資料庫密碼與 API 金鑰，並支援自動輪替。
易混淆：KMS 管的是加密金鑰，不負責輪替資料庫密碼。

👉 一行口訣：密碼自動輪替 -> Secrets Manager。

**28.** 答案：**D**

ACM 可為 ALB、CloudFront 佈署 TLS 憑證並自動續期。
易混淆：WAF 是防護 Web 攻擊的防火牆，不管理憑證。

👉 一行口訣：HTTPS 憑證、自動續期 -> ACM。

**29.** 答案：**AC**

WAF 防護 SQL injection、XSS 等第七層攻擊；Shield 防護 DDoS。
易混淆：Inspector 是漏洞掃描，Macie 是 S3 敏感資料探索，Config 是組態合規，都不是網路攻擊防護。

👉 一行口訣：Web 攻擊 -> WAF；DDoS -> Shield。

**30.** 答案：**C**

Inspector 掃描 EC2、容器映像檔與 Lambda 的軟體漏洞與網路暴露。
易混淆：GuardDuty 是偵測帳號與工作負載的異常行為（威脅偵測），不掃漏洞。Detective 是事後調查安全事件的根因。

👉 一行口訣：掃漏洞 -> Inspector；偵測異常行為 -> GuardDuty。

**31.** 答案：**A**

GuardDuty 分析 CloudTrail、VPC Flow Logs 與 DNS 紀錄，偵測異常與惡意行為。
易混淆：Inspector 看的是軟體漏洞，不是行為。

👉 一行口訣：異常行為、惡意 IP -> GuardDuty。

**32.** 答案：**B**

Macie 以機器學習在 S3 中發現並保護 PII 等敏感資料。
易混淆：GuardDuty 偵測威脅，不分類資料內容。

👉 一行口訣：S3 裡的 PII -> Macie。

**33.** 答案：**D**

CloudTrail 記錄帳號內的 API 呼叫（誰、何時、從哪裡）。
易混淆：Config 記錄的是資源組態的變化與合規，不是呼叫者；CloudWatch 看的是指標與日誌。

👉 一行口訣：誰呼叫了 API -> CloudTrail；資源組態怎麼變 -> Config。

**34.** 答案：**C**

Artifact 提供 AWS 的合規報告與協議下載。
易混淆：Audit Manager 蒐集的是客戶自己使用 AWS 的稽核證據，不是 AWS 本身的合規報告。

👉 一行口訣：下載 AWS 的 SOC／ISO 報告 -> Artifact。

**35.** 答案：**A**

NACL 作用在子網路層級，無狀態、可設定允許與拒絕。
易混淆：安全群組作用在執行個體層級、有狀態、只能設定允許。

👉 一行口訣：子網路、無狀態、可拒絕 -> NACL；執行個體、有狀態、只允許 -> 安全群組。

## 領域三：雲端技術與服務

**36.** 答案：**B**

in-memory 資料處理需要大量記憶體，選記憶體最佳化（R、X 系列）。
易混淆：運算最佳化針對高 CPU 需求，不是記憶體。

👉 一行口訣：大量記憶體 -> Memory optimized；高 CPU -> Compute optimized。

**37.** 答案：**D**

事件觸發、無伺服器、依執行次數與時間計費，是 Lambda。
易混淆：Beanstalk 與 Lightsail 仍有伺服器要管理；EC2 更是。

👉 一行口訣：事件觸發、不管伺服器、依次數計費 -> Lambda。

**38.** 答案：**C**

Fargate 讓 ECS（與 EKS）執行容器而不需自行管理 EC2 叢集。
易混淆：EC2 launch type 需要自己管理 EC2；ECR 是儲存容器映像檔，不執行容器。

👉 一行口訣：容器、不管伺服器 -> Fargate；映像檔倉庫 -> ECR。

**39.** 答案：**A**

Beanstalk 讓開發者上傳程式碼，其餘佈建與管理由 AWS 處理。
易混淆：CloudFormation 是用範本自己定義每個資源（IaC）；CodeDeploy 只負責佈署程式碼。

👉 一行口訣：上傳程式碼、自動處理環境 -> Elastic Beanstalk；範本定義資源 -> CloudFormation。

**40.** 答案：**B**

CloudFormation 以範本描述基礎設施，可跨帳號與 Region 重複建立。
易混淆：Beanstalk 是託管應用環境，不是通用的基礎設施範本。

👉 一行口訣：IaC、範本、重複建立 -> CloudFormation。

**41.** 答案：**AC**

Instance store 是連接主機的實體儲存，延遲極低、IOPS 高，但資料在停止或終止後消失。
易混淆：永久保存、可快照屬於 EBS 的特性。

👉 一行口訣：暫時性、極低延遲 -> Instance store；永久、可快照 -> EBS。

**42.** 答案：**D**

Intelligent-Tiering 依存取頻率自動在階層間移動，適合存取模式不明的資料。
易混淆：Standard-IA 與 One Zone-IA 適合已知很少存取的資料，且有最低儲存天數與取回費用。

👉 一行口訣：存取模式不明、自動分層 -> Intelligent-Tiering。

**43.** 答案：**A**

Deep Archive 是 S3 中成本最低的儲存類別，取回時間以小時計（標準取回約 12 小時，細節以官方文件為準）。
易混淆：Glacier Instant Retrieval 可毫秒取回，單價較高；Standard-IA、One Zone-IA 是即時存取的類別。

👉 一行口訣：長期保存、極少存取、成本最低 -> Glacier Deep Archive。

**44.** 答案：**C**

EFS 是託管的 NFS 檔案系統，可跨 AZ 多台 Linux 同時掛載，容量自動伸縮。
易混淆：EBS 通常只掛載到單一 EC2（限定在同一 AZ）；S3 是物件儲存，不是檔案系統掛載。

👉 一行口訣：多台 Linux 共用檔案 -> EFS；單機區塊儲存 -> EBS。

**45.** 答案：**B**

Read Replica 以非同步複寫分攤讀取流量。
易混淆：Multi-AZ 是同步複寫、用於容錯移轉，備援不接受讀取流量（一般 Multi-AZ 部署）。

👉 一行口訣：同步、容錯移轉 -> Multi-AZ；非同步、分攤讀取 -> Read Replica。

**46.** 答案：**A**

DynamoDB 是無伺服器的鍵值／文件資料庫，個位數毫秒延遲、自動擴展。
易混淆：RDS 是關聯式，需選擇執行個體規格；Redshift 是資料倉儲；Neptune 是圖形資料庫。

👉 一行口訣：無伺服器、鍵值、毫秒延遲 -> DynamoDB。

**47.** 答案：**DE**

Redshift 是全託管的資料倉儲，採欄式儲存，用於分析型（OLAP）查詢。
易混淆：OLTP 交易處理用 RDS 或 Aurora；鍵值用 DynamoDB；圖形用 Neptune。

👉 一行口訣：分析、資料倉儲、欄式 -> Redshift；交易 -> RDS/Aurora。

**48.** 答案：**D**

Athena 無伺服器，直接以 SQL 查詢 S3 的資料，依掃描量計費。
易混淆：Redshift 需要佈建叢集；EMR 是大數據叢集；Kinesis 處理串流資料。

👉 一行口訣：直接用 SQL 查 S3、無伺服器 -> Athena。

**49.** 答案：**C**

SQS 是訊息佇列，生產者與消費者解耦，消費者依自己速度處理。
易混淆：SNS 是發布／訂閱，把訊息推送給多個訂閱者；Kinesis 是即時串流資料。

👉 一行口訣：佇列、解耦、緩衝 -> SQS；一對多推送 -> SNS。

**50.** 答案：**B**

Route 53 是 DNS 服務，可搭配健康檢查與 Failover 路由政策切換到備援網站。
易混淆：CloudFront 是快取內容的 CDN；Global Accelerator 是以固定 Anycast IP 導流，不是 DNS。

👉 一行口訣：DNS 解析與容錯移轉 -> Route 53。

**51.** 答案：**A**

CloudWatch 蒐集指標並可設定告警與通知。
易混淆：CloudTrail 記錄 API 呼叫；Config 記錄資源組態；X-Ray 追蹤應用請求。

👉 一行口訣：指標、告警 -> CloudWatch。

**52.** 答案：**D**

EC2 Auto Scaling 依指標自動增減執行個體數量。
易混淆：ELB 分配流量但不增減執行個體；Route 53 與 CloudFront 與擴展執行個體無關。

👉 一行口訣：自動增減執行個體 -> Auto Scaling；分配流量 -> ELB。

**53.** 答案：**B**

NAT gateway 讓私有子網路出站連網，且不允許外部主動連入。
易混淆：Internet gateway 讓公有子網路雙向連網；NAT gateway 有按小時與資料處理量的費用，用完要注意刪除。

👉 一行口訣：私有子網路出站連網 -> NAT gateway；公有子網路 -> Internet gateway。

**54.** 答案：**C**

Direct Connect 提供專用私有連線，頻寬與延遲穩定，不走公共網際網路。
易混淆：Site-to-Site VPN 加密但走公共網際網路，延遲不穩定。

👉 一行口訣：專用線路、不經公網 -> Direct Connect；加密、走公網、快速建立 -> VPN。

**55.** 答案：**BE**

ALB 運作於第七層，可依 URL 路徑或標頭路由，支援 HTTP/2 與 WebSocket。
易混淆：每個 AZ 靜態 IP 是 NLB；第三層是 Gateway Load Balancer；ELB 都是單一 Region，不會跨 Region。

👉 一行口訣：第七層、依路徑路由 -> ALB；第四層、靜態 IP、極高效能 -> NLB。

**56.** 答案：**A**

Global Accelerator 提供兩個固定 Anycast IP，流量走 AWS 全球骨幹網路，並可跨 Region 快速容錯移轉，支援 TCP 與 UDP。
易混淆：NLB 只在單一 Region 內；Route 53 是 DNS；CloudFront 針對 HTTP(S) 內容快取。

👉 一行口訣：Anycast IP、AWS 骨幹、跨 Region、TCP/UDP -> Global Accelerator。

**57.** 答案：**D**

Transcribe 把語音轉成文字。
易混淆：Polly 是文字轉語音；Comprehend 是文字分析（情緒、實體）；Rekognition 是影像與影片分析。

👉 一行口訣：語音轉文字 -> Transcribe；文字轉語音 -> Polly。

## 領域四：帳單、計價與支援

**58.** 答案：**C**

Compute Savings Plans 承諾每小時花費，自動適用 EC2、Fargate 與 Lambda，並可更換家族與 Region。
易混淆：Standard RI 綁定特定執行個體家族與 Region，彈性較低；Spot 可能被中斷，不適用穩定用量。

👉 一行口訣：承諾每小時金額、跨服務彈性 -> Compute Savings Plans。

**59.** 答案：**A**

Spot 可節省最多約 90%，但可能被中斷，適合可中斷、可重跑的批次。
易混淆：RI 與 Savings Plans 適合穩定長期用量，不適合以「最低成本、可中斷」為目標。

👉 一行口訣：可中斷、最低成本 -> Spot。

**60.** 答案：**D**

Dedicated Hosts 提供實體伺服器，可看見 socket 與 core，適合沿用綁定實體資源的授權（BYOL）。
易混淆：Dedicated Instances 是單租戶硬體，但不提供主機層級的可視性與授權綁定。

👉 一行口訣：BYOL、實體 socket/core 授權 -> Dedicated Hosts。

**61.** 答案：**B**

Budgets 可設定預算與門檻，費用實際或預測超過時發出通知。
易混淆：Cost Explorer 用來分析歷史與預測，不負責通知；Pricing Calculator 是部署前估價。

👉 一行口訣：預算與告警 -> Budgets；分析歷史費用 -> Cost Explorer；事前估價 -> Pricing Calculator。

**62.** 答案：**BD**

資料傳入 AWS 通常不收費；同一 AZ 內使用私有 IP 的 EC2 之間傳輸也不收費。
易混淆：跨 Region、傳到網際網路、經由 NAT gateway 處理，都會產生費用。

👉 一行口訣：傳入免費；同 AZ 私有 IP 免費；跨 AZ、跨 Region、傳出網際網路要收費。

**63.** 答案：**C**

依本教材與考試範圍，Basic 與 Developer 只提供核心的安全與服務配額檢查，Business 以上才有完整的 Trusted Advisor 檢查。
易混淆：AWS 近期調整過支援方案內容，細節請以官方文件為準，報考前再對照一次。

👉 一行口訣：完整 Trusted Advisor 檢查 -> Business 以上。

**64.** 答案：**A**

Organizations 的合併帳單可彙總用量、取得數量折扣，並只收一張帳單。
易混淆：Cost Explorer 與 CUR 是分析與報表工具，不改變帳單方式。

👉 一行口訣：多帳號、一張帳單、彙總折扣 -> Consolidated Billing。

**65.** 答案：**B**

Pricing Calculator 用於部署前估算預估費用。
易混淆：Cost Explorer 分析的是已發生的費用；Budgets 是設定預算與通知。

👉 一行口訣：部署前估價 -> Pricing Calculator。

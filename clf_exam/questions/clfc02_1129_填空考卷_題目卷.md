## 一、運算與部署（12 格）

**1.** 想快速架一個小型網站或部落格，要求固定月費、把虛擬伺服器、儲存、網路與靜態 IP 打包好，不想研究 VPC，應該選（①）。

**2.** 公司已經有一個寫好的 Web 應用程式，想直接上傳程式碼，讓 AWS 自動佈建 EC2、負載平衡與 Auto Scaling，不想自己設定這些資源，應該選（②）。它的底層仍然會用到（③）。

**3.** 程式由事件觸發才執行、不想管任何伺服器、依執行時間計費，應該選（④）。

**4.** 只負責把應用程式碼自動佈署到既有的伺服器，不會幫你建立 EC2 等基礎設施的服務是（⑤）。

**5.** 用範本（基礎設施即程式碼）定義並一次建立整組資源，應該選（⑥）。

**6.** 需要完全控制作業系統、自己安裝各種軟體、自己設定網路，應該選（⑦）。

**7.** Lightsail 與 EC2 相比，Lightsail 的特色是（⑧）、（⑨）；EC2 的設定較複雜、計價也比較複雜。

**8.** Beanstalk 與 CloudFormation 相比，Beanstalk 是你負責（⑩），AWS 負責佈建環境；CloudFormation 則是你要自己用（⑪）定義每個資源。

**9.** Lambda 與 Beanstalk 相比，要把現有的 Web 應用程式搬上去，Lambda 需要先把程式（⑫）。

## 二、Secrets Manager、KMS、ACM（6 格）

**10.** 資料庫密碼、API 金鑰需要安全保存，並且定期自動輪替，應該選（⑬）。

**11.** 要建立與管理用來加密資料的金鑰，應該選（⑭）。

**12.** 網站要啟用 HTTPS，需要 SSL/TLS 憑證並且自動續期，應該選（⑮）。

**13.** 「credentials」在 Secrets Manager 的意思是（⑯），不是網站連線用的 SSL/TLS 憑證。

**14.** KMS 管的是加密（⑰），不是用來儲存與輪替 API 金鑰。

**15.** 三個服務一句話分界：帳密與 API 金鑰 -> （⑱）；加密金鑰 -> （⑲）；HTTPS 憑證 -> （⑳）。

## 三、Artifact 與 Audit Manager（4 格）

**16.** 要下載 AWS 本身的合規報告，例如 ISO 27001、SOC 報告，應該選（㉑）。

**17.** 除了報告之外，要檢視並簽署 BAA 這類協議，也是在（㉒）。

**18.** 要自動蒐集「公司自己帳戶」的稽核證據，並對照 PCI DSS 等框架的控制項，應該選（㉓）。

**19.** 記憶法：證據是 AWS 的 -> （㉔）；證據是你自己的 -> Audit Manager。

## 四、計價方案（5 格）

**20.** 短期、不可中斷、不想綁約的工作負載，應該選（㉕）。

**21.** 工作可以重跑、被中斷也沒關係、要成本最低，應該選（㉖）。

**22.** Reserved Instances 與 Savings Plans 都是用一到三年的（㉗）換折扣。

**23.** Compute Savings Plans 涵蓋 EC2、（㉘）與 Lambda；EC2 Instance Savings Plans 只涵蓋 EC2。

## 五、零碎缺口（2 格）

**24.** 不改程式碼與架構、原樣搬到 AWS，是 6R 的（㉙）；只是把自己架的資料庫改成 RDS 代管、其他維持不變，是 6R 的 Replatform；重新設計成微服務或無伺服器，是 Refactor。

**25.** 需要 AWS 指派專屬 Technical Account Manager，應該選（㉚）支援方案。

**今日目標**：打開 A15 狀態機裡「呼叫模型」那一格，看懂模型怎麼產生文字、怎麼收錢，再手寫一個由模型決定下一步的 Agent 迴圈。

**六個名詞**

| 名詞                      | 意思                                                       |
| ------------------------- | ---------------------------------------------------------- |
| token                     | 模型讀寫的單位，可能是一個字、半個字、一個標點             |
| context window（脈絡長度）| 一次能放的 token 上限，輸入和輸出都算                      |
| hallucination（幻覺）     | 講得很有把握，但沒有根據或是錯的                           |
| temperature / Top P       | 取樣參數：前者改機率分布形狀，後者砍掉機率尾巴             |
| toolUse / toolResult      | 模型開的單／你的程式執行完送回的結果                       |
| stopReason                | 模型停下來的原因：`tool_use` 要用工具，`end_turn` 回答完了 |

## 一、模型內部機制：一塊一塊接，不是故障是本性

**三件事**

- 模型一次只產生一小塊（token），看前面全部 token 替下一塊算機率，挑一個接上，再拿整串去算下一個
- 同一句話問兩次答案不同、不知道也答得很有把握，**不是故障，是模型本來的運作方式**
- 模型沒有記憶：看得到前面講過什麼，是因為你的程式每次都把對話紀錄再送一次

**幻覺：寧可猜，也不說不知道**

- 像考選擇題，空著一定零分，模型寧可猜
- 原因：每一步挑一個接得上的 token，擅長寫像樣的句子，不擅長查證

| 對策 | 做法                                              |
| ---- | ------------------------------------------------- |
| 一   | 把資料放進去，讓它照著答（下一單元 RAG）          |
| 二   | 提示裡明講「不知道就說不知道」                    |
| 三   | Bedrock Guardrails 比對回答和你給的資料，不符就擋 |

> 注意：Guardrails 能減少幻覺，但不能消除；重要的決定還是要有人看。

**長對話退化**

- 對話越長，每次送的 token 越多，越慢、越貴
- 超過上限：程式常把最舊的訊息丟掉；被丟掉又沒重新送進去的內容，模型就看不到
- 沒超過也會退化：放越多，越難找回特定資訊，叫 **context rot（脈絡腐化）**
- 對策：換話題就開新對話；舊內容先摘要再放回去（見第五章）
- 講義實例：今晚用的 Nova 2 Lite 脈絡長度 1M token、最多輸出 64K；token 數看 API 回傳，**不要自己估**

**CCP 考點**

- 網站上要對話式聊天機器人 → **Amazon Lex**；Textract 擷取掃描文件文字、Glue 資料整合、Rekognition 分析圖片影片都是誘答（題庫 CLF-C02 第 0598 題）

> 一句話：模型只會接下一個 token，幻覺是本性，對策是給資料、講明規則、加護欄。

## 二、定價模型：輸出約 8 倍，快取讀取只要四分之一

**Nova 2 Lite 每百萬 token（美東維吉尼亞北部，隨需；講義 2026-10-22）**

| 類型       | 單價（美元） | 備註                       |
| ---------- | ------------ | -------------------------- |
| 輸入 token | 0.33         |                            |
| 輸出 token | 2.75         | 要一個一個生成，所以貴     |
| 快取讀取   | 0.0825       | 寫入快取不另收費           |

- 固定的開頭放前面，才吃得到快取

**估月成本 ＝ 次數 × token × 單價**

假設每天 1,000 次對話 × 30 天，每次輸入 3,000 token（其中固定開頭 2,000）、輸出 300 token：

| 項目         | 沒用快取              | 固定開頭吃到快取                            |
| ------------ | --------------------- | ------------------------------------------- |
| 輸入         | 90M × 0.33 ＝ 29.70   | 一般 30M × 0.33 ＝ 9.90；快取 60M × 0.0825 ＝ 4.95 |
| 輸出         | 9M × 2.75 ＝ 24.75    | 一樣 24.75                                  |
| **一個月**   | **54.45 美元**        | **39.60 美元**                              |

> 注意：前提是固定開頭一直有人用、每次都吃到快取；Agent 一個問題是好幾次呼叫，而且一次比一次長，實際會更貴。對照本專案月預算 30 美元，呼叫量一大就要先估再開。

> 一句話：輸出最貴、快取最省，估成本就是次數乘 token 乘單價。

## 三、取樣參數與結構化輸出

**取樣：temperature 改形狀，Top P 砍尾巴**

| 參數        | 作用                                                         |
| ----------- | ------------------------------------------------------------ |
| temperature | 低 → 分布變陡，幾乎都選最高機率的字；高 → 分布變平，冷門字也有機會 |
| Top P       | 從機率最高的往下累加，到達 P 就停，只從這些候選裡抽          |

- 要穩定可重現（抽欄位、分類、選工具、測試）設 **0**；要多樣（想店名、想標題）才調高
- 檢查點：候選貓 0.5、狗 0.3、兔子 0.2，Top P 0.8 → 從**貓和狗**抽（0.5＋0.3＝0.8 就停）

**結構化輸出：提示是請求，Schema 是模具**

| 做法       | 結果                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 只靠提示   | 「請只回 JSON」只是比較可能照做；會多話、包反引號、型別錯、被截斷    |
| JSON Schema | Bedrock 限制回應照規格走（`outputConfig` 的 `textFormat`，type 為 `json_schema`） |

- 模具只保證形狀：**內容對不對、有沒有被截斷（看 `end_turn`）還是要自己檢查**
- 不是每個模型都支援，先到模型卡確認

> 一句話：要穩定設低溫，要 JSON 就用 Schema，但內容仍要驗。

## 四、工具呼叫原理：模型開單，你的程式執行

**五步往返**

1. 你的程式呼叫 `converse`，帶對話與 `toolConfig`（工具描述）
2. 模型回 `stopReason: tool_use` 與 `toolUse`（`toolUseId`、`name`、`input`，可能好幾塊）——**只是一段文字**
3. 你的程式真的去執行函式（例：`get_order_status("A001")`）
4. 再呼叫 `converse`，user 訊息加 `toolResult`（同一個 `toolUseId`）；還要工具就重複
5. 模型回 `stopReason: end_turn`，給出回答

> 白話：模型只開單（要用哪個工具、帶什麼參數）；**真正執行、權限、錯誤處理都在你的程式**。

- 檢查點：`stopReason` 為 `tool_use` 要求呼叫 `get_order_status`，真正執行查詢的是**你的應用程式**，不是模型、也不是 Bedrock（Converse 這種寫法由你執行）
- 安全意涵：工具權限就是你程式的 IAM 權限，最小權限要自己守

> 一句話：模型只開單，執行與權限都在你的程式。

## 五、Context Engineering：管理什麼東西進到脈絡

**脈絡 ＝ 每次送進模型的整包**：系統提示、工具描述、對話、工具結果、查回來的資料。目標是**只放最少、但訊號最強的內容**。

| 手段             | 做法                                           |
| ---------------- | ---------------------------------------------- |
| 摘要             | 對話太長，把前面整理成一段重點，換掉原文       |
| 清掉舊工具結果   | 要用再查一次，只留下「查過」的紀錄             |
| 需要時再查       | 不要一開始把整本手冊塞進去（下一單元 RAG）     |
| 寫筆記           | 把進度寫到外部檔案，下次再讀回來               |

- 固定的內容放前面，才吃得到快取（呼應第二章）

**CCP 考點**

- 員工用單一智慧搜尋介面、用自然語言問問題取得特定答案 → **Amazon Kendra**；Connect 是客服中心、Lex 是聊天機器人、Comprehend 分析文字，都是誘答（題庫第 0699 題）

> 一句話：脈絡不是越多越好，是每次只放最少但訊號最強的。

## 六、實作：手刻一個 Agent

> 講義未標預期費用；本實作用 Bedrock Nova 2 Lite（`us.amazon.nova-2-lite-v1:0`），會花抵用金，**沒有建立任何資源，不用刪**。

**流程**：問題 → `converse`（TODO 1：附上 `toolConfig`）→ 看 `stopReason`：`tool_use` 就 TODO 2 解析 `toolUse`、`run_tool` 執行、TODO 3 把 `toolResult` 以 user 角色塞回對話、下一輪；`end_turn` 印出回答並加總 token；其他（如 `max_tokens`）報錯停下。**最多 5 輪（`MAX_TURNS`）**。

**必做步驟：先離線，再連線**

1. **準備**：`python3 -m venv .venv`、`source .venv/bin/activate`、裝 boto3
2. **離線跑一次**：`python3 agent.py --offline`，看到 TODO 1 還沒寫
3. **寫 TODO 1**：`tool_config` 改成 `{"tools": specs}`
4. **寫 TODO 2、3**：離線跑到印出 `OFFLINE OK`
5. **連 Bedrock 真的問一次**：`python3 agent.py`，對照紙上追蹤和每輪 token 數
6. **交件**：貼上離線與連線兩次的完整輸出

**加碼與收尾**

- 呼叫不存在的工具：`--offline --ghost`，再拿掉 `--offline`；把 `TOOLS.get` 改成 `TOOLS[name]`，看程式從回傳 error 變成直接當掉
- 對照實驗：`python3 experiments.py temp`（同提示設 0 和 1 各跑幾次）、`python3 experiments.py json`（只用提示要純 JSON，數破格次數）
- 實驗二（脈絡長度）會花抵用金，講義說今晚不做
- 收尾：Billing 主控台看抵用金

## Takeaway

1. 模型只會接下一個 token，幻覺是本性，要用資料、規則、Guardrails 與人工檢查補
2. 輸出貴、快取省；要穩定設低溫；JSON 用 Schema
3. 工具由你的程式執行，權限與錯誤處理都是你的責任
4. 脈絡要管理：摘要、清舊結果、需要時再查、寫筆記

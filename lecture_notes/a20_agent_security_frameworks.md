# a20 | Agent 安全與框架選型：外部內容當資料，框架可選、評估必備

> 來源：`lectures/A20 Agent 安全與框架選型 投影片.pdf`（共 41 頁；講義日期 2026-10-29；出處為 Bedrock Guardrails、AgentCore Policy、LangGraph／CrewAI／Bedrock AgentCore 文件）

**今日目標**：網頁隱藏字叫 Agent 匯出使用者，它真的去叫工具了。學會辨識間接注入、疊五層防禦、設資源上限，並用問題形狀選框架。

**貫穿例子**：阿芯豆花店客服為了回答「你們運費是不是比別家貴」去抓競品網頁，網頁內容進了對話就變成攻擊面。安全不是單章咒語，是 A05（網路）、A18（工具邊界）、A19（軌跡）紀律的加總。

---

## 一、指令注入：間接才是真風險

**為什麼對 Agent 特別危險**

| 原因             | 說明                                               |
| ---------------- | -------------------------------------------------- |
| 它會叫工具       | 被騙之後不是只講錯話，是真的執行動作               |
| 外部內容很多     | 網頁、郵件、資料庫欄位都可能進對話                 |
| 只靠提示不夠     | 「不要被騙」寫在系統提示裡，擋不住藏字             |

**兩種注入**

| 類型     | 誰把指令帶進來             | 風險                   |
| -------- | -------------------------- | ---------------------- |
| 直接注入 | 使用者打字下指令           | 相對好察覺             |
| 間接注入 | 藏在工具讀到的網頁、郵件、欄位 | **實務真風險**     |

**攻擊路徑（豆花客服）**：顧客問運費 → Agent 呼叫 `fetch_page` 讀競品網頁 → 頁面帶回隱藏字 → 整段塞進 prompt 被當指令 → 誤呼叫高危工具 `export_users`。**工具邊界 ＝ 信任邊界**：讀頁回傳一旦當指令，高危工具就可能被叫。

**迷思澄清框**

**我們的使用者很乖，所以很安全？**

- ✗ 使用者不會輸入奇怪指令，所以安全
- ✓ 間接注入不需要使用者配合；攻擊字可以藏在它去讀的外部內容裡

**Quiz**：間接指令注入最常出現在 → **工具讀到的網頁、郵件或欄位內容**（只有使用者剛打的那句是直接注入）。

> 一句話：外部內容當資料，不當指令。

## 二、五層防禦：少一層就有洞

| 層  | 防禦         | 做法                                                       |
| --- | ------------ | ---------------------------------------------------------- |
| ①   | 指令／資料分離 | 系統提示與規則放指令區，網頁／郵件／欄位只進資料區並標記來源，fetch 結果只進資料區 |
| ②   | 最小權限     | 讀頁角色只有 `fetch`；客服角色有 `get_order`、`lookup_policy`；高危工具（`export_users`）另開人工確認。**被注入時，損害範圍 ＝ 工具清單** |
| ③   | 輸出驗證     | 工具參數與輸出用 schema 驗證                               |
| ④   | 人工確認     | 高危操作呼叫前確認（見下）                                 |
| ⑤   | 網路隔離     | A05 的 egress 白名單                                       |

**危險操作：人工確認怎麼做**

1. 列出高危工具清單（退款、匯出使用者、改權限、刪資料）
2. 呼叫前跳出確認卡，顯示工具名、參數摘要、影響範圍
3. 人按同意才執行；不同意就中止並寫入軌跡
4. 把拒絕案例送進評估集，避免以後又繞過確認

> 確認不是裝飾，是可稽核的閘門。

**網路隔離（回收 A05）**：被注入後若可任意出網，資料會被外送；工具執行環境只允許連到已知網域。網路是最後一道，**不能代替最小權限**。

**護欄產品：外圍不是唯一防線**

| 產品               | 作用                       |
| ------------------ | -------------------------- |
| Bedrock Guardrails | 擋注入／敏感內容           |
| AgentCore Policy   | 閘道層允許／拒絕           |

- 外圍防護 ≠ 唯一防線；仍要自測攻擊句

**疊層總覽**：應用（分離、最小權限、確認）→ 產品（Guardrails／Policy）→ 資源（迭代／超時／預算）→ 網路（egress 白名單）

> 一句話：防禦要疊層，單一產品擋不住。

## 三、資源護欄：停得下來才安全

- 為什麼上限也是安全：空轉會燒錢（模型費與工具費在迴圈裡疊加）、掛住會占額度（一個 session 卡死別人也被拖）、攻擊可放大（注入成功後若無上限損害滾雪球）

| 護欄       | 防什麼       |
| ---------- | ------------ |
| 最大迭代   | 空轉         |
| 超時       | 掛住         |
| token 預算 | 脈絡爆       |
| 成本告警   | 帳單爆       |

**豆花客服的四個上限（示例，不是官方標準）**

- 最大迭代 8 次；超過就向顧客說請稍後再試並轉人工
- 超時 45 秒；token 預算單次對話上限寫死
- 成本告警：日費用超過設定就通知值班，不是月底才看帳單（對應 Budgets／CloudWatch 告警）

> 一句話：停不下來的 Agent 就是不安全的 Agent，四個上限都要有。

## 四、失敗圖鑑：先對症狀再翻軌跡

| 症狀         | 軌跡徵狀（接回 A19）                   | 對症下藥                         |
| ------------ | -------------------------------------- | -------------------------------- |
| 無限工具迴圈 | 同一工具反覆出現                       | 迭代上限＋重複偵測               |
| 脈絡爆掉     | token 曲線陡升、延遲變長               | 摘要／截斷／隔離                 |
| 回傳過長     |                                        | 強制摘要上限                     |
| 硬編造參數   | `tools/call` 參數過不了 schema         | schema 驗證拒絕                  |

> 一句話：值班先對圖鑑，再翻軌跡，症狀清楚處方才快。

## 五、框架選型：很多場景不用框架

**為什麼常選錯**：先追名字（不問問題長什麼樣）；抽象稅被低估（省了樣板，卻增加除錯與鎖定成本）；框架 ≠ 安全帽（評估與護欄仍不可省）。

**判斷表：先看問題形狀**

| 問題形狀             | 選擇            | 代表       |
| -------------------- | --------------- | ---------- |
| 工具少、近循序       | 手寫迴圈        | 豆花三工具夠 |
| 複雜分支與狀態       | 狀態機／圖      | LangGraph 類 |
| 快速多角色原型       | 角色協作        | CrewAI 類  |
| 託管權限／觀察／護欄 | 雲端託管        | AgentCore 類 |

- **預設：能手寫迴圈就先手寫**，狀態爆炸才引入框架、才願付抽象稅

**抽象稅**

| 項目     | 說明                                   |
| -------- | -------------------------------------- |
| 除錯變遠 | 錯誤可能藏在框架內部狀態機             |
| 鎖定風險 | 團隊被框架的概念模型綁住               |
| 安全不打包 | 評估、護欄、權限仍要自己做           |

**迷思澄清框**

**上了框架就自動安全？**

- ✗ 選了知名框架，注入與資源失控就會被擋掉
- ✓ 框架幫你管狀態與編排；安全仍靠分離、權限、護欄、評估

> 一句話：框架可選，評估與護欄不可省；很多場景手寫迴圈就夠。

## Takeaway

1. 外部內容當資料不當指令；間接注入才是實務真風險
2. 防禦要疊五層：分離、最小權限、驗證、確認、網路
3. 迭代、超時、token、成本，四個上限都要有
4. 選型先看問題形狀，預設手寫迴圈；框架不等於安全
